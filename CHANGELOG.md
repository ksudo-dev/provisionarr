# Changelog

All notable changes to Provisionarr are documented here.

## Unreleased

### Added

- Explicit existing-stack and managed-stack first-run choices
- Separate Movie and TV sections for discovery and search results
- Public contribution lanes and promotion rules for onboarding preview work
- Owner-only connection and native API tests for Sonarr, Radarr, Prowlarr, and
  qBittorrent
- Fresh-stack onboarding for Sonarr and Radarr root folders, qBittorrent
  download clients, separate TV and movie categories, and Prowlarr application
  links
- Preview, apply, verification, private backup, and rollback for the guided
  onboarding plan
- Explicit indexer-provider boundary: administrators add provider credentials
  in Prowlarr
- Generated four-service Compose bundle and dry-run, apply, verify, and
  data-preserving rollback commands
- Docker and native Node.js installation paths
- Tailnet-only HTTPS guidance alongside LAN HTTP and reverse-proxy profiles

### Changed

- Managed-stack onboarding is labeled as preview work until clean ARM64 and
  AMD64 installation, upgrade, and rollback checks pass
- The setup workflow reports service capability and configuration state in
  plain language while keeping upstream credentials server-side
- Fresh-stack onboarding treats qBittorrent as a configured download client in
  both ARR applications instead of a separate read-only check

### Security

- Onboarding writes remain owner-only and require an unexpired preview
- Prowlarr provider credentials stay in Prowlarr and aren't generated by
  Provisionarr
- Release documentation excludes secrets, private infrastructure details, and
  unverified test claims

## 1.0.0

- Separate owner and household-user accounts
- Per-user display names, notification preferences, and optional profile
  pictures
- Native Sonarr and Radarr title lookup with season-aware requests
- Request confirmation, per-user history, request allotments, and storage holds
- Emby-backed library synchronization and recommendations
- Persistent per-user notification inboxes with optional email delivery
- Owner-only download, import, activity, health, audit, notification, and user
  administration
- Safe failed-release rejection through the owning ARR service
- Docker deployment, CI, security policy, and tailnet-only HTTPS guidance
- Versioned SVG artwork and favicon
- Upgrade, backup, and rollback instructions that preserve `/data`
